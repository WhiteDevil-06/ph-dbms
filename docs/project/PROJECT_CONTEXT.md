# Project Context and Operational Background

## 1. Project Title and Context
**Project Title**: Intelligent Data Management and Operational Analytics for Autonomous Post-Harvest Material Handling Systems

In agricultural robotics, post-harvest handling involves sorting, grading, packing, and routing harvested produce (such as apples, tomatoes, or citrus) through autonomous mobile platforms equipped with robotic manipulators and AI vision systems.

The post-harvest operational cycle follows a disciplined multi-stage pipeline:
```text
Vision Capture → Object Detection → Localization → Decision Logic → Platform Navigation → Arm Manipulation → Quality Verification
```

---

## 2. The DBMS Operational Boundary
A central principle of this project is the strict separation between the **Robotics Real-Time Control Loop** and the **Data Management and Operational Analytics Layer (DBMS)**:

```text
┌────────────────────────────────────────────────────────┐
│     EXTERNAL ROBOTICS SYSTEM (Out of Scope for DBMS)   │
│  - Real-time sensor processing (camera stream / lidar) │
│  - Motor speed / navigation steering controls          │
│  - Manipulator inverse kinematics and joint servos     │
│  - Hardware safety interlocks and emergency stops      │
└───────────────────────────┬────────────────────────────┘
                            │ (Structured JSON Events)
                            ▼
┌────────────────────────────────────────────────────────┐
│               POST-HARVEST DBMS LAYER                  │
│  - Operational session lifecycle tracking              │
│  - Task queuing, priority, and state persistence       │
│  - Spatial detection metadata and model provenance     │
│  - Operational decisions and rationale logging         │
│  - Execution times, device states, and outcomes        │
│  - System faults, warnings, and resolution history     │
│  - Interactive analytics dashboard for operators       │
└────────────────────────────────────────────────────────┘
```

### Explicit Prohibitions:
- The DBMS project **must never** attempt to act as a robot controller.
- No low-level hardware control code (e.g. motor PWM, inverse kinematics, CAN bus drivers) may be written.

---

## 3. Project Phase: Simulation-Only Integration
The physical robotic platform and manipulator are currently under construction by the robotics team. Consequently:
- **Zero Live Robot Integration**: There are no physical robot hardware connections or field telemetry feeds in this phase.
- **Deterministic Synthetic Generation**: All operational data is generated by an internal Python simulation harness (`simulator/`).
- **Reproducibility**: The generator utilizes a configurable pseudorandom seed (default `seed = 42`) ensuring identical datasets for evaluation and testing.
- **Data Provenance**: Every record, row, and document inserted into MySQL or MongoDB carries an explicit provenance tag (`SIMULATED` or `MANUAL_TEST`).
- **Persistent UI Notice**: The React dashboard displays an uninterrupted "SIMULATION DATA" indicator banner whenever simulated records are rendered.
- **Truthful Academic Reporting**: The team will never present simulation records as actual physical robot telemetry or real-world field results.

---

## 4. Media Storage Boundary
Autonomous vision systems generate image frames and video streams. However:
- The DBMS scope in this phase is restricted to **detection metadata** (bounding boxes, class labels, confidence scores, timestamps, camera device IDs, and frame reference strings).
- **No Image/Video Subsystem**: The DBMS does not store raw binary image files, video streams, or object storage blobs (S3/MinIO) unless an explicit future requirement is approved by the project lead.

---

## 5. Object Tracking Boundary
- Each `detection_id` represents an individual, independent spatial observation captured in a frame.
- **No Inter-frame Tracking**: Do not assume object re-identification or continuous trajectory tracking across video frames unless a formal tracking algorithm and schema extension are approved.
