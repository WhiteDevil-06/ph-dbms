## 2. Project Context
This project, titled **"Intelligent Data Management and Operational Analytics for Autonomous Post-Harvest Material Handling Systems"**, provides the data management, persistence, monitoring, and operational analytics layer for an autonomous post-harvest agricultural robotics system. In this project phase, all operational data is generated by a deterministic simulator. Live robot hardware integration is out of scope. Ramcharan is responsible for building a browser-based React dashboard that surfaces operational records, detections, decisions, operations, device states, and analytics, while making simulation provenance unmistakably transparent to the user.

---

## 3. Ownership and Explicit Non-Ownership
- **Owns**:
  - Complete browser-based dashboard and frontend user interface.
  - Page routing, responsive layout, reusable UI components, forms, filters, and status badges.
  - Interactive charts and visual operational analytics using Recharts.
  - State management, data fetching, and caching using TanStack Query.
  - Consumption of documented FastAPI endpoints from Rahul.
  - Comprehensive handling of loading, empty, and error states across all pages.
  - Prominent, persistent "SIMULATION DATA" indicator across all pages whenever simulated data is active.
  - Frontend setup guide, component catalog, and API dependency documentation in `frontend/README.md`.
- **Explicit Non-Ownership & Strict Prohibitions**:
  - Must **never** connect browser code directly to MySQL or MongoDB.
  - Must **never** place database credentials, passwords, or connection strings in frontend code.
  - Must **never** invent endpoints or response fields that are not documented in `docs/api/API_CONTRACT.md`.
  - Must **never** independently change the database schema or simulate fake live robot telemetry.

---

## 4. Step-by-Step Responsibilities
1. Review the dashboard specifications in `docs/project/DASHBOARD_SPECIFICATION.md`.
2. Initialize the React + TypeScript + Vite + Tailwind CSS frontend application in `frontend/`.
3. Set up the layout shell with top navigation, breadcrumbs, sidebar, and the global simulation banner.
4. Implement TypeScript type definitions corresponding strictly to backend Pydantic schemas.
5. Create API service clients and custom hooks for data retrieval.
6. Build out core views: Overview, Sessions, Tasks, Detections, Operations, Decisions, System Events, and Analytics.
7. Implement error handling, fallback components, and empty states.
8. Validate responsive layout across desktop and tablet screen sizes.
