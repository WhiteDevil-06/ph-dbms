## Decision Records

### [DEC-01] Elimination of Accidental Self-Referencing Foreign Key in `TASK`
- **Date**: 2026-11-07
- **Status**: **CONFIRMED**
- **Decider**: Rakshith Raghavendra (Project Lead & Database Architect)
- **Context**: In `RELATIONAL_SCHEMA_SOURCE.jpg`, `TASK` listed both `PK task_id` and `FK task_id`. ER diagram shows `SESSION [1]` contains `[N] TASK`.
- **Decision**: Remove `FK task_id` from `TASK`. Define `task_id VARCHAR(36) PRIMARY KEY` and `session_id VARCHAR(36) NOT NULL` with `FOREIGN KEY (session_id) REFERENCES session(session_id) ON DELETE CASCADE`.
- **Consequences**: Eliminates recursive self-reference bug; enables normal task creation linked to parent sessions.

### [DEC-02] Omission of Typo Column `rescription` in `DECISION`
- **Date**: 2026-11-07
- **Status**: **CONFIRMED**
- **Decider**: Rakshith Raghavendra (Project Lead & Database Architect)
- **Context**: `RELATIONAL_SCHEMA_SOURCE.jpg` contains an attribute named `rescription` in `DECISION` alongside `rationale`. `ER_DIAGRAM_SOURCE.jpg` shows only `rationale`.
- **Decision**: Do not create a column named `rescription`. Maintain `rationale TEXT NOT NULL` as the single authoritative justification attribute.
- **Consequences**: Prevents dead/redundant columns and maintains clean schema terminology.

### [DEC-03] Inclusion of `device_id` Foreign Key on `OPERATION` Table
- **Date**: 2026-11-07
- **Status**: **CONFIRMED**
- **Decider**: Rakshith Raghavendra & Rahul
- **Context**: `RELATIONAL_SCHEMA_SOURCE.jpg` depicts `FK device_id` on `OPERATION`. The ER diagram did not draw a direct line between `OPERATION` and `DEVICE`.
- **Decision**: Adopt `device_id VARCHAR(36) NOT NULL` as a foreign key on `OPERATION` referencing `device(device_id)`.
- **Consequences**: Accurately tracks which physical actuator (robotic arm, gripper, conveyor) executed each post-harvest operation.

### [DEC-04] Authoritative Data Store Allocation for Detections and System Events
- **Date**: 2026-11-07
- **Status**: **CONFIRMED**
- **Decider**: Team Consensus (Rakshith Raghavendra, Rahul, Ramcharan)
- **Context**: DFD Level 1 allocates `DETECTION` to MongoDB `D2`, whereas `RELATIONAL_SCHEMA` depicts it as a relational table. `SYSTEM_EVENT` appears in both D1 and D2 in DFD Level 1.
- **Decision**:
  1. `DETECTION`: Authoritative store is MongoDB (`detections` collection). No duplicate SQL table is maintained.
  2. `SYSTEM_EVENT`: MySQL stores structured operational events (`system_event` table); MongoDB stores high-frequency raw sensor streams (`telemetry_logs` collection).
- **Consequences**: Clear separation of concerns; avoids split-brain dual-write synchronization bugs.

---

### [DEC-05] Nullability of `DECISION.task_id` and `SYSTEM_EVENT.operation_id`
- **Date**: 2026-11-07
- **Status**: **CONFIRMED**
- **Decider**: Rakshith Raghavendra (Project Lead & Database Architect)
- **Context**: Decisions can occur at the session level before a specific task is spawned. System events can be generated by idle hardware without an active operation.
- **Decision**: Define `DECISION.task_id` and `SYSTEM_EVENT.operation_id` as `NULLABLE` foreign keys.
- **Consequences**: Allows system-wide and device-level event logging without forcing artificial placeholder operations.

### [DEC-06] Modular Monolith Architecture
- **Date**: 2026-11-04
- **Status**: **CONFIRMED**
- **Decider**: Team Consensus
- **Context**: Need a robust, maintainable architecture without the operational overhead of microservices, service meshes, or message brokers.
- **Decision**: Build a single FastAPI backend with decoupled layers (`api/`, `services/`, `repositories/`) and a single React frontend.
- **Consequences**: Simple local development on Windows 11, clean deployment, zero distributed network failure points.

---

### [DEC-07] MySQL Python Driver Selection for Windows Python 3.13
- **Date**: 2026-11-04
- **Status**: **CONFIRMED**
- **Decider**: Rahul & Rakshith Raghavendra
- **Context**: Host system runs Python 3.13.14 on Windows 11. `mysqlclient` requires Microsoft C++ Build Tools which may fail to compile in local academic environments.
- **Decision**: Standardize on `PyMySQL` (`mysql+pymysql://`) with `cryptography` for SQLAlchemy connections.
- **Consequences**: 100% reproducible pure-Python installation on Windows without C++ compiler prerequisites.
