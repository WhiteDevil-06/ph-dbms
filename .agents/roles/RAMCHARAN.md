## 2. Project Context
This project, titled **"Intelligent Data Management and Operational Analytics for Autonomous Post-Harvest Material Handling Systems"**, provides the data management, persistence, monitoring, and operational analytics layer for an autonomous post-harvest agricultural robotics system. In this project phase, all operational data is generated by a deterministic simulator. Live robot hardware integration is out of scope. Ramcharan is responsible for building a browser-based React dashboard that surfaces operational records, detections, decisions, operations, device states, and analytics, while making simulation provenance unmistakably transparent to the user.

**Backend Current Status (Phase 5 Completed & Verified)**:
- The backend, MySQL 8.4, and MongoDB 8.0 databases are containerized and fully operational via Docker Compose.
- Live services run on:
  - Backend API: `http://localhost:8000` (FastAPI)
  - Interactive API Docs (Swagger): `http://localhost:8000/docs`
  - Healthcheck: `GET http://localhost:8000/health`
  - Simulation Control API:
    - `GET /api/v1/simulation/status` (live record counts and active seed)
    - `POST /api/v1/simulation/generate` (synthesizes seeded records: small, medium, demo)
    - `POST /api/v1/simulation/reset` (safely purges simulated records with `confirm_purge=true`)
- All records in MySQL and MongoDB carry explicit provenance `SIMULATED`.
- The frontend dev server runs on `http://localhost:5173` with CORS origins pre-configured in the backend.

## 4. Step-by-Step Responsibilities
1. **Start Backend Infrastructure**: Run `docker compose up -d` in repository root to ensure MySQL, MongoDB, and FastAPI backend are running and healthy on `http://localhost:8000`.
2. **Review Specifications**:
   - Read `docs/project/DASHBOARD_SPECIFICATION.md` for layout and widget requirements.
   - Read `docs/api/API_CONTRACT.md` for API schemas, route signatures, and query parameters.
3. **Initialize Frontend Application**:
   - Scaffold Vite + React + TypeScript in `frontend/` with Tailwind CSS, Lucide icons, Recharts, and TanStack Query.
   - Configure Vite proxy in `frontend/vite.config.ts` (`/api` and `/health` -> `http://localhost:8000`) to avoid local CORS handling.
4. **Build Core Layout Shell**:
   - Implement top navigation, sidebar, breadcrumbs, and live system status pill (polling `/health`).
   - Implement the permanent, unclosable global simulation banner:
     `[ SIMULATION DATA ACTIVE ] All records are generated from deterministic simulation models.`
5. **Implement Simulation Management Widget**:
   - Wire UI controls to `GET /api/v1/simulation/status` to show total simulated counts.
   - Wire "Generate Dataset" modal to `POST /api/v1/simulation/generate` (seed and scale options).
   - Wire "Reset Data" button with confirmation modal to `POST /api/v1/simulation/reset`.
6. **Implement TypeScript Contracts & API Clients**:
   - Create TypeScript interfaces strictly matching backend schemas (`Session`, `Task`, `Operation`, `Detection`, `Decision`, `SystemEvent`).
   - Create custom data hooks using TanStack Query for caching and auto-refetching.
7. **Build Primary Views**:
   - Overview / Executive Summary (KPI summary cards, recent sessions, system event feed).
   - Sessions View (session list, status badges, drill-down details).
   - Tasks & Operations View (timeline, status breakdown, task-to-operation hierarchy).
   - Detections & AI Analysis (bounding box visualization, confidence distribution chart, class breakdown).
   - Hardware & AGV Telemetry (battery SoC %, motor current, IMU orientation).
   - Analytics & Reporting (grading distribution, failure rate metrics, cycle times).
8. **Testing & Build Verification**:
   - Verify zero TypeScript compiler errors (`tsc --noEmit`).
   - Verify ESLint passes cleanly (`npm run lint`).
   - Verify production build succeeds (`npm run build`).
